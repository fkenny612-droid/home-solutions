# Truck Loads — Driver app

Native iOS/Android app for drivers, with Google turn-by-turn **truck** navigation
via the [Navigation SDK](https://github.com/googlemaps/react-native-navigation-sdk)
(`@googlemaps/react-native-navigation-sdk`, Beta). Separate from the Easyfix app
in `apps/mobile`; dispatchers use the web board at `/truck-loads`.

## How navigation works

1. Driver taps **Navigate to pickup / delivery** on a load.
2. The app gets a GPS fix and calls `POST /truck-loads/driver/loads/:id/navigation`.
3. The API asks the Routes API for a `travelMode: TRUCK` route from that position,
   using the rig's height/width/length/axles, its weight (empty to pickup, laden
   to delivery) and the load's hazmat classes, and returns a **route token**.
4. The Navigation SDK follows that token. Re-routes keep the truck restrictions
   encoded in it. If no truck route is available the app stops rather than
   falling back to car routing.
5. On arrival: *Loaded — start trip to delivery* at pickup, *Mark delivered*
   (with an optional POD note) at delivery.

Truck routing covers the contiguous US (GA) and Japan (experimental) only.

## Google Cloud setup

In the same Google Cloud project as the API's `GOOGLE_MAPS_API_KEY`:

- Enable **Navigation SDK**, **Maps SDK for Android**, **Maps SDK for iOS**.
- Create an app key restricted to those APIs and to this app's Android package
  + signing SHA-1 and iOS bundle id → `GOOGLE_NAVIGATION_API_KEY`.
- The API's server key needs **Routes API** (large vehicle routing).

If the key isn't authorized for the Navigation SDK, the app shows a clear error
on the navigation screen (`NOT_AUTHORIZED`).

## Running it

The Navigation SDK is native code, so this **does not run in Expo Go** — use a
development build.

```sh
cd apps/truck-driver
npm install                     # standalone npm project, not in the pnpm workspace
cp .env.example .env            # set EXPO_PUBLIC_API_URL and GOOGLE_NAVIGATION_API_KEY

# Local build (Android Studio / Xcode installed):
npx expo run:android
npx expo run:ios

# Or cloud builds with EAS:
eas init                        # creates the EAS project, writes its id
# add GOOGLE_NAVIGATION_API_KEY (sensitive) and EXPO_PUBLIC_API_URL as
# EAS environment variables (expo.dev → project → Environment variables, or `eas env:create`)
eas build --profile development --platform android
```

Before the first store build, replace the placeholder `com.truckloads.driver`
bundle id / package in `app.config.ts`.

In dev builds the navigation screen has a **Simulate** button that drives the
route so you can test guidance at a desk.

## Native setup

`android/` and `ios/` are generated by `expo prebuild` (gitignored). The
package ships no config plugin, so `plugins/withGoogleNavigation.js` applies its
install steps: Maps API key (Android manifest + iOS `AppDelegate`), core library
desugaring, Jetifier, minSdk 24, and iOS `location`/`audio` background modes.

Versions: Expo SDK 57 (React Native 0.86) → Navigation SDK RN `0.16.x`
(`0.17+` needs React Native 0.87).
